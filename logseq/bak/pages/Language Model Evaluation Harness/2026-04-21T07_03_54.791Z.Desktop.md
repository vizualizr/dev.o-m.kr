- ## Introduction
	- 크게 다음과 같이 구분한다.
		- 언어 모델 평가 도구(Language Model Evaluation Harness)
			- 다양한 벤치마크를 일괄 실행해 모델 성능을 비교 평가한다.
			- 학습이 완료된 모델이 가진 능력을 평가하는 도구다.
		- 에이전트 하네스(Agent Harness)
			- 실무 워크플로임을 가정하고 LLM 기반 에이전트이 가진 문제 해결 능력 및 이에 필요한 자원 활용 능력을 테스트하기 위한 실험용 프레임워크다.[^1]
- ## Steps
	- 에이전트 하네스(Agent Harness)
		- 목표
			- 실무에서 에이전트가 시행착오를 반복할 때 인간이 개입해 최종 목표에 도달하는 과정 자체를 자동화하기 위함이다. 즉 하네스는 시행착오 과정에서 인간이 개입하는 과정을 시뮬레이션한다.
		- 시험 환경은 격리실행(sandbox)와 평가 도구(evaluator)로 구성한다.
			- 대상을 샌드박스 안에서 격리한 후 시험한다.
				- 도커 및 유사 컨테이너 기술
				- E2B(Edge-to-Browser) SDK: 에이전트가 접근할 수 있는 샌드박스 인프라에 API를 구축해 에이전트가 직접 작성한 코드로 문제를 해결하고 워크플로를 실행할 수 있는 환경을 구축한다.
				- Wasm(WebAssembly)
				- 자원(cpu, 메모리) 등을 제한한다. 에이전트가 과도한 자원을 동원하는 과정에서 시스템을 보호하고 과도한 자원 낭비를 방지하기 위함이다.
		- 평가
			- 관찰가능성(observability)을 바탕으로 에이전트의 사고 과정을 검증하려 한다.
			- 산출물이 코드라면 코드를 직접 평가할 수 있는 결정적 도구를 사용한다.
			- 비결정적 결과는 다른 고성능 LLM으로 해당 결과를 평가한다.
		- 상태 관리
			- 에이전트의 문제 해결 과정을 경로 형태로 저장해 막다른 골목에 다다를 경우 이전 지점으로 선회시켜 다른 경로로 안내한다.
		- 보안
			- 실시간 가드레일이 실행 단계마다 실시간으로 개입해 주어진 정책과 비교하며 필요한 경우 답변 노드를 선회토록 한다.
	- 토큰 과다 소모 방지 정책
		- 컨텍스트 캐싱 - 문제 해결 과정에서 변화가 없는 부분(소스코드, 보안 정책)을 캐시한다.
		- 하네스를 계층화한다. 문제를 작은 단위로 분할해 역할에 따라 개별 하네스에 전달해 최종 결과를 취합한다. 비용 또한 같은 방법으로 절감할 수 있다. 쉬운 문제는 저비용 하네스에, 어려운 문제는 고비용 하네스에 분담할 수 있다.
		- 증분피드백
		- MCP 활용
- ## Troubleshooting
	- 개인에게 적합한가?
		- 기업 단위에서 실제 인력을 대체하기 위한 용도지 개인 개발자가 자신의 워크플로우 개선에 쓰기에는 소모되는 자원이 과다하다. 개인용 호스트에서 감당할 수 없는 수준이다.
		- 자산으로 삼는 데이터의 출처를 개인으로 한정하거나 소규일 경우 데이터 편향 문제가 발생한다.
